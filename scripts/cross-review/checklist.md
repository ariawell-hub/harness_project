# 검증 체크리스트 (10.1절 검증 항목)

작성자는 PR을 준비 완료로 바꾸기 전에 이 체크리스트로 자체 리뷰하고 결과를 PR에 남긴다. 2단계 CI 검증자도 같은 버전을 쓴다(10.2절 (2)).

- [ ] 수용 기준을 모두 충족하고, 근거(테스트·검증 결과)가 있다
- [ ] 정확성: 버그, 엣지 케이스(빈 입력, 경계값, 동시성, 실패 경로)
- [ ] 테스트가 실제로 동작을 검증한다. `test-effect` 예외가 있으면 사유가 타당하다. 새로 만든 모듈을 import하는 테스트 파일(`test-effect` 판정 줄의 "단언 실패 아님")은 단언을 직접 확인했다(R5)
- [ ] 아키텍처 경계·황금 원칙(docs/core-beliefs.md) 위반이 없다
- [ ] 계획 "관련 파일" 범위 밖 변경이 있다면 이유가 PR에 있다(R18)
- [ ] 관련 문서를 갱신했거나, 갱신이 필요 없는 이유를 적었다(R8)
- [ ] 보안: 입력 검증, 인증·인가, 시크릿 노출, 위험 작업(14절)
- [ ] (보호 경로 변경 시) 검사를 약화시키지 않았다(R4, R9)
- [ ] 발견 사항마다 처리가 적혀 있다(8.3절)

지적 등급: P0 치명(데이터 손실·보안·크래시) / P1 결함(AC 미충족·재현 가능한 버그·무의미한 테스트) → 병합 차단. P2 개선 / P3 취향 → 비차단.
