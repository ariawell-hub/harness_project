# Actions 비용: 판단 절차와 기준선

비공개 리포에서 하네스를 돌릴 때 드는 GitHub Actions 비용을 재는 방법, 제작자가 정한 예산, 기준선, 판단 절차를 적는다. 절감 수단의 후보와 결정은 여기 없다(계획 `20261121-actions-cost-design`의 step2가 ADR로 적는다).

이 문서의 예산 값, 기준선, 기록 표는 검사 스크립트가 보존 기록과 견준다([lab/actions-cost/README.md](../../lab/actions-cost/README.md)). 고친 뒤에는 `node lab/actions-cost/check-doc.ts`를 돌린다.

## 왜 재는가

- GitHub Actions는 비공개 리포에서 과금된다. 과금은 job마다 돈 시간을 분으로 올림해 센다(10초 돈 job도 1분이다).
- 이 리포는 2026-11-21에 공개로 바뀌어 청구가 0이다. 하지만 하네스를 쓸 프로젝트는 비공개여야 한다(제작자 결정). 그래서 비공개 리포에서 감당할 수 있는 Actions 비용이 요구사항이다.
- 공개 리포는 청구가 0이라 청구서로는 볼 수 없다. 그래서 실행 기록으로 "비공개였다면 청구됐을 값"을 잰다.
- 요금제의 포함 사용량은 리포마다 따로 주어지지 않는다. 계정의 비공개 리포 전체가 나눠 쓴다. 프로젝트가 늘면 한 프로젝트가 쓸 수 있는 몫이 준다.

## 재는 방법

```bash
# 기간을 재서 표준 출력에 낸다(GitHub은 읽기만 한다)
node scripts/harness.ts actions-cost --since 2026-11-17 --until 2026-11-20
# 읽은 입력을 보존 기록으로 남긴다(있는 파일은 덮어쓰지 않는다)
node scripts/harness.ts actions-cost --since <날짜> --until <날짜> --save lab/actions-cost/<날짜>_<날짜>.jsonl
# 남긴 입력으로 다시 계산한다(GitHub을 읽지 않는다)
node scripts/harness.ts actions-cost --from lab/actions-cost/<날짜>_<날짜>.jsonl
```

계산 규칙:

- **올림**: job마다 돈 초를 분으로 올림한다(최소 1분). 워크플로 하나에 job이 여럿이면 job마다 따로 올림한다.
- **시도**: 다시 실행한 시도는 따로 센다. 같은 job을 두 번 돌리면 두 번 청구된다.
- **단가**: 2코어 Linux 러너(`ubuntu-latest` 등)는 분당 $0.006이다. 단가를 확인하지 못한 러너와 self-hosted 러너의 분은 청구 분과 금액에 넣지 않고 따로 적는다.
- **돌지 않은 job**: 건너뛴 job과 시작하지 못한 job은 0분이다.
- **PR**: 실행을 PR에 이을 수 있을 때만 잇는다. 가릴 수 없는 실행은 "PR을 찾지 못함"에 따로 보인다. 기본 브랜치의 `push` 실행은 "PR 밖"이다.
- **보존 기록**: `--save`가 남기는 파일에는 계산에 드는 값만 있다(실행 id, 시도, 허용 목록에 있는 이름, 날짜, 돈 초, 러너 라벨, PR 번호, head 순번). `--from`은 그 파일만으로 같은 값을 낸다.

이 값이 뜻하는 것과 뜻하지 않는 것:

- 공개 리포에서는 실제 청구가 아니다. 같은 실행이 비공개 리포에서 돌았다면 청구됐을 값이다.
- 단가를 모르는 러너는 금액에 없다. 그런 분이 있으면 금액은 실제보다 작다.
- 검증자(Claude, Codex)의 구독 사용량은 들지 않는다. Actions 러너가 돈 시간만 센다.
- 앱의 테스트·빌드 시간은 프로젝트마다 다르다. 이 리포의 `check`는 하네스 자체 테스트를 돌린 시간이고, 하네스를 쓰는 프로젝트의 `check`는 그 프로젝트의 테스트·빌드 시간이다.
- "PR 하나당 청구 분"과 "PR 하나당 금액"은 PR 밖 실행(병합 뒤 main의 `check` 등)까지 PR 수로 나눈 값이다. PR에 이어진 실행만 나눈 값은 요약 표에 따로 있다.

Issue #170 본문의 임시 집계(청구 단위 3,391분)와 다르다. 이 기준선은 4,028분으로 637분 많다. 임시 집계는 최근 실행 1,000건만 읽었고 다시 실행한 시도를 따로 세지 않았다. 이 기준선은 기간의 실행을 모두 읽고 시도마다 센다.

## 판단 절차

- 기준이 되는 입력: 기준은 보존 기록(`lab/actions-cost/`의 `.jsonl` 파일)이다. 확인은 `--from`으로 한다. 잰 뒤에 누가 그 기간의 실행을 다시 실행하거나 실행 기록이 지워져 GitHub을 다시 읽은 값이 달라져도 보존 기록을 바꾸지 않는다. 워크플로·job 이름이 바뀌어 `--from`의 출력이 달라지면 같은 보존 기록으로 다시 계산해 붙인다.
- 다시 재는 때: 절감 수단을 하나 넣을 때마다 넣기 전과 뒤를 같은 길이의 기간으로 `--save`해 재고, 아래 "기록" 표에 한 줄을 더한다. 수단을 둘 이상 한꺼번에 넣으면 어느 수단의 효과인지 가를 수 없으므로 하나씩 넣는다.
- 판단 시점 1(절감 수단마다): 넣기 전과 뒤의 기록 행을 견줘 효과를 본다. "PR 하나당 금액"과 "PR head 하나당 청구 분"이 줄었는지 본다.
- 판단 시점 2(파일럿을 비공개 리포에서 시작하기 전): 가장 최근 기록 행의 판단이 `예산 안`이면 시작한다. 아니면 다음 절감 수단을 넣고 다시 잰다.
- 판단 시점 3(이 리포를 다시 비공개로 돌릴지 정할 때): "30일 환산 금액"을 계정의 월 예산과 견준다. 이 리포의 몫만큼 다른 비공개 프로젝트가 쓸 포함 사용량이 준다는 것을 함께 본다.
- 효과가 없을 때: 전후의 값이 줄지 않았으면 그 수단을 되돌린다. 되돌린 것도 "기록" 표에 한 줄로 남긴다.
- 파일럿 실측: 파일럿 대상 리포에서 `check`의 실제 시간을 한 번 재서 환산에 넣는다. 이 리포의 `check` 시간은 하네스 자체 테스트의 시간이라 파일럿 프로젝트의 값이 아니다.
- 예산을 넘는 결정: 지출 한도, 요금제, 러너를 바꾸는 것은 제작자가 정한다([절차서](workflow.md) 7절). 봇은 예산 안에 들지 않는다는 것과 모자라는 폭을 보고한다.

## 기록

`기간`부터 `30일 환산 금액`까지 여섯 칸은 `--from` 출력의 "기록 칸" 행을 그대로 옮긴다. `판단`은 `예산 안`·`예산 밖`·`판단 못 함` 가운데 하나로 시작한다. 정하는 순서: PR이 없으면 `판단 못 함`, 단가를 아는 러너의 금액만으로 PR 하나당 금액이 $0.18을 넘으면 `예산 밖`, 그렇지 않고 단가를 모르는 러너의 분이 있으면 `판단 못 함`, 그 밖은 `예산 안`이다. 검사 스크립트는 칸의 글이 아니라 보존 기록으로 계산한 전체 금액으로 판단을 다시 정해 견준다.
