# ADR-0008: 비공개 리포의 Actions 비용 — 예산과 절감 수단

- 날짜: 2026-11-22
- 상태: 채택 (제작자가 2026-11-22에 묶음 "호스팅 유지"를 골랐다. 이 주제를 다시 볼 때는 호스팅을 유지한 채 더 줄이는 길과 묶음 "검증 밖으로"를 먼저 본다)
- 관련: 설계서 E2·E3, 5절(R7), 6절, 10.2절부터 10.4절, 13.2절, 18절 Q12·Q13, [기준선과 판단 절차](../harness/actions-cost.md), [검사 스크립트](../../lab/actions-cost/README.md), Issue #170, Issue #126, TD-40, TD-49

## 배경

하네스를 쓸 프로젝트는 비공개 리포여야 하고, 비공개 리포에서는 Actions의 표준 러너가 유료다. 이 ADR은 [기준선과 판단 절차](../harness/actions-cost.md)의 수치로 절감 수단을 견주고, 제작자가 고를 묶음을 제시한다.

기준선(2026-11-17부터 2026-11-20까지, 이 리포가 비공개였던 나흘)과 예산은 이렇다.

- 기준선: PR 40개, PR head 175개에 4028분이 청구됐다($24.17). PR 하나당 100.7분($0.604)이고 30일로 환산하면 $181.26이다.
- 예산: PR 하나당 30분($0.18), 프로젝트 하나의 월 PR 100개, 계정의 월 $18(제작자 결정, 2026-11-21). 기준선은 예산의 3.4배다.

비용이 나오는 곳은 이렇다.

- 워크플로별: `check` 39.4%(PR에서 PR당 31.7분, 병합 뒤 main에서 8.0분), 판정 워크플로 둘 40.3%(`judge-codex` 26.5%, `judge-claude` 13.8%), `gates` 19.6%, `review-trigger` 0.7%.
- PR head 하나당 21.2분이 든다(`check` 7.2분, `gates` 4.5분, `judge-codex` 6.1분, `judge-claude` 3.1분, `review-trigger` 0.2분). PR 하나의 head는 평균 4.4개다(중앙값 3개, 가장 많은 PR은 23개).
- 올림으로 붙은 몫이 청구의 40.8%(1644.6분)다. 돈 job 2384개 가운데 1968개가 1분 안에 끝났는데 1분씩 청구됐다.
- `check`를 뺀 하네스의 몫(게이트, 판정, `review-trigger`)만 PR당 61.0분($0.366)으로 예산의 두 배다. 프로젝트의 `check`가 0분이어도 예산을 넘는다.
- `check` 한 번은 `test`를 돌리면 평균 10.1분이고 거의 전부가 `test`다(한 실행에서 `check` 단계 798초 가운데 775초). 이 리포의 `test`는 하네스 자체 테스트라 파일럿 프로젝트의 값이 아니다. 파일럿 리포에서 한 번 재서 넣어야 한다(판단 절차의 "파일럿 실측").

이미 한 것과 하지 않기로 했던 것(TD-49)은 이렇다.

- 한 것: 한 라운드의 대응을 한 번에 push하는 규칙(절차서 5절, Issue #126), 테스트가 읽지 않는 경로만 바꾼 변경에서 `test` 건너뛰기(6절, Issue #129. 기준선의 뒤 이틀에 들어 있다), 재현 테스트가 없는 판정에서 재현 job을 띄우지 않기(Issue #143).
- 하지 않기로 했던 것: 병합 뒤 main의 `check`가 PR에서 통과한 트리를 다시 쓰기(2026-11-19, 필수 체크의 구조 변경이라 접었다. 아래 A5), 제목만 바뀐 수정에서 `gates`를 건너뛰기(건너뛰는 실행이 진행 중인 판정을 취소한다. 아래 F1).

이 ADR은 Actions의 청구만 다룬다. 검증자의 구독 사용량(Q12)은 다루지 않는다.

### 확인한 외부 사실

2026-11-22에 공식 문서에서 읽은 것이다. 후보표의 "확인 상태"가 이 출처를 가리킨다.

- 러너의 분당 단가: Linux 2코어 x64 $0.006, Linux 2코어 arm64 $0.005, Linux 1코어 x64 $0.002. job마다 쓴 시간을 분으로 올려 센다. (https://docs.github.com/en/billing/reference/actions-runner-pricing)
- 포함 사용량은 분이 아니라 금액으로 정해져 있다: Free $12, Pro $18, Team $18. 공개 리포의 표준 러너와 self-hosted 러너의 사용은 포함 사용량을 줄이지 않는다. 사용량은 리포의 소유자에게 청구된다. (https://docs.github.com/en/billing/concepts/product-billing/github-actions)
- 1코어 러너(`ubuntu-slim`)는 비공개 리포에서 쓸 수 있다. VM이 아니라 공유 VM 위의 컨테이너에서 돌고(job마다 새 컨테이너), job 제한이 15분이고, 도구가 적게 깔려 있다. arm64 2코어 러너(`ubuntu-24.04-arm`)도 비공개 리포의 표준 러너 표에 있다. (https://docs.github.com/en/actions/reference/runners/github-hosted-runners)
- self-hosted 러너에 2026-03-01부터 분당 $0.002를 받겠다던 발표는 연기됐고 새 날짜는 없다. (https://github.blog/changelog/2025-12-16-coming-soon-simpler-pricing-and-a-better-experience-for-github-actions/)
- self-hosted 러너는 깨끗한 일회용 환경을 보장하지 않고 워크플로의 코드에 오염된 채 남을 수 있다. 러너를 쓸 리포를 제한하는 러너 그룹은 조직의 기능으로 적혀 있다. (https://docs.github.com/en/actions/reference/security/secure-use)
- 확인하지 못한 것: 개인 계정 리포에서 쓸 수 있는 외부 러너 서비스, Actions 밖 서비스의 요금, 구독 토큰을 계속 켜 둔 기기에서 쓰는 것이 약관에 맞는지, 검증자 CLI가 arm64 Linux와 1코어 러너의 이미지에서 도는지.

## 되돌리는 조건

수단을 넣은 뒤 같은 길이의 기간을 다시 재서(기준선 문서의 "기록" 표), PR 하나당 금액이 줄지 않았으면 그 수단을 되돌린다. 금액이 줄었어도 잃는 보장이 후보표에 적은 것보다 크면 되돌린다: 1코어 러너에서 job이 실패하거나 1분을 넘기는 경우, 요청한 head만 검증하면서 병합 직전에 실패가 몰려 PR이 오래 열리는 경우, main의 `check`를 건너뛴 뒤 main이 깨진 채 발견되는 경우가 그렇다. 러너의 단가나 포함 사용량이 바뀌면 묶음의 금액을 다시 계산한다. 되돌린 것도 "기록" 표에 한 줄로 남긴다.
