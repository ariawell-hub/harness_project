# ADR-0004: Q20 시험 리포에는 시험 기간에만 봇을 초대한다

- 날짜: 2026-11-11
- 상태: 채택 (제작자 대화 결정)
- 관련: 설계서 Q20, 10.4절, 13.3절, 19절 2단계, E5, [ADR-0003](ADR-0003-bot-token-classic-pat.md)

## 배경

- 로드맵 2단계는 Q20 시험 통과가 착수 조건이다. 시험은 하네스 리포가 아니라 빈 테스트 리포에서 한다(설계서 10.4절). `pull_request_target` 판정 job은 main의 정의로 돌기 때문에 실험 워크플로를 main에 병합해야 하고, 주입 문구를 담은 공격 PR도 일부러 올려야 하기 때문이다.
- ADR-0003은 봇을 하네스 리포 하나에만 초대한다고 정했다. 클래식 PAT는 토큰으로 리포 범위를 제한할 수 없어서, 봇이 초대된 리포에는 모두 통한다.

## 결정

- 시험 리포는 제작자 계정 소유의 비공개 리포 하나다. 이름은 만들 때 정한다(예: `harness-q20-lab`).
- 봇은 시험 기간에만 Write로 초대한다. Admin·Maintain은 주지 않는다. Q20 결과를 하네스 리포에 기록하면 제작자가 초대를 철회한다.
- 시험 리포의 설정은 하네스 리포와 같게 둔다.
  - main 보호: PR 필수, 필수 승인 0, "Require approval of the most recent reviewable push" 끔, 우회 금지, force push·삭제 금지
  - Actions: 기본 권한 읽기 전용, "Actions가 PR 생성·승인" 끔, 리포 수준 시크릿 없음
- environment·시크릿·시험용 검증 App은 제작자가 만든다. 봇은 admin이 아니라 만들 수 없다.
- 비밀은 가짜 토큰이 원칙이다. 진짜 자격증명(Codex 구독 인증 등, 설계서 13.3절)은 그 항목을 시험할 때만 넣는다.
  - 넣기 전에 environment를 main 전용으로 제한하고, 시험 리포 main의 필수 승인을 1로 올려 제작자만 병합할 수 있게 한다.
  - 시험이 끝나면 그 자격증명을 교체(재발급)하고 필수 승인을 0으로 되돌린다.
- 시험 결과는 하네스 리포에 남긴다. Q20 실행 계획의 발견 사항, 설계서 Q20 행, 필요하면 새 ADR.

## 확인 방법

봇 토큰으로 실행한다.

```bash
# 시험 중: 하네스 리포와 시험 리포 두 개만 나와야 한다
# 철회 뒤: ariawell-hub/harness_project 하나만 나와야 한다(ADR-0003 확인 방법과 같다)
gh api 'user/repos?affiliation=owner,collaborator,organization_member&per_page=100' --jq '.[].full_name'
```

## 결과와 남는 위험

- 시험 기간에는 봇 토큰이 시험 리포에도 통한다. 시험 리포에는 가짜 토큰과 시험 코드만 있으므로 피해는 작다.
- main에 병합된 워크플로는 main 전용 environment의 비밀을 받는다. 진짜 자격증명이 있는 동안 봇이 워크플로를 병합할 수 있으면 그 비밀을 빼낼 수 있다. 그래서 그 기간에는 필수 승인을 1로 올리고, 기간을 짧게 하고, 끝나면 교체한다.
- 철회를 잊으면 ADR-0003의 범위 제한이 깨진다. Q20 실행 계획의 마지막 step 수용 기준에 위 확인 명령의 "철회 뒤" 결과를 넣는다.

## 버린 대안

- **제작자가 시험 리포를 직접 다루고 에이전트는 초안만 만든다**: ADR-0003을 그대로 지키지만, 시험마다 제작자가 push·PR을 해야 해서 시험이 느려진다.
- **시험 전용 두 번째 봇 계정**: 범위는 깔끔하지만 관리할 계정·토큰·2단계 인증이 하나 더 늘어난다.
- **하네스 리포에서 바로 시험**: 실험 워크플로와 공격 PR이 하네스 main에 들어간다(설계서 10.4절).
