# 비공개 리포에서의 Actions 비용 설계: 공개 기간에 재고, 예산과 절감 수단을 정한다

## 목표와 수용 기준

2026-11-18과 11-20에 Actions의 포함 사용량과 지출 한도가 바닥나 모든 job이 시작되지 않았다(Issue #126, #170). 2026-11-17~20의 실측으로는 월 $180~320의 속도다. 제작자는 2026-11-21에 이 리포를 공개로 바꿨고(표준 러너 무료), 하네스를 실제로 쓸 프로젝트는 비공개여야 한다고 정했다. 그래서 비공개 리포에서 감당할 수 있는 Actions 비용이 하네스의 요구사항이 된다.

공개 리포는 청구가 0이라 청구서로는 비용을 볼 수 없다. 이 계획은 (1) Actions 실행 기록에서 "비공개였다면 청구됐을 값"을 재는 명령을 만들고, (2) 그 값으로 판단하는 절차와 기준선을 문서로 남기고, (3) 절감 수단을 조사해 제작자가 고를 수 있는 결정 기록(ADR)으로 만든다. 고른 수단의 구현은 이 계획에 넣지 않는다.

수용 기준:

1. `node scripts/harness.ts actions-cost --since <YYYY-MM-DD> --until <YYYY-MM-DD>`가 그 기간(UTC 날짜, 양끝 포함)에 만들어진 Actions 실행의 job을 읽어, job마다 올림한 분과 러너 단가로 "비공개였다면 청구됐을 값"을 계산해 마크다운으로 표준 출력에 낸다. GitHub에 쓰지 않는다. `--save`를 주지 않으면 파일을 쓰지 않는다.
2. 계산 규칙이 step0의 정의대로이고, 고정한 입력으로 계산 함수를 부르는 테스트가 값을 단언한다: 돌지 않은 job은 0분, 돈 job은 초를 분으로 올림(최소 1분), 다시 실행한 시도는 job 기록의 시도 번호로 갈라 따로 청구(일부 job만 다시 실행한 경우 포함), 단가를 모르는 러너와 self-hosted 러너는 금액에 넣지 않고 따로 보인다.
3. 출력에 합계, 워크플로별, job별, 날짜별, PR별, PR 하나당 평균(PR에 이어진 실행만 센 값과, 예산과 견주는 PR 밖 포함 값을 이름을 달리해 따로), PR head 하나당 평균(push 한 번의 추정값. 분자와 분모가 같은 실행 집합이다), 올림으로 붙은 몫, 30일 환산값이 있다. PR 밖 실행(main 등)과 PR을 찾지 못한 실행은 숨기지 않고 각각 따로 합산한다.
4. 자료를 끝까지 읽지 못하면 종료 코드 2로 끝나고 표준 출력에 결과를 내지 않는다. 받은 수가 맞아도 실행이나 job이 중복으로 온 응답(읽는 동안 목록이 바뀌어 빠진 것이 있을 수 있다)은 끝까지 읽지 못한 것이다. 형식에 어긋나거나 줄 수가 머리 줄과 다른 보존 기록도 같다. 인자나 기간이 틀리면 GitHub을 읽기 전에 종료 코드 1로 끝난다.
5. 출력에는 수, PR 번호, 날짜, 그리고 명령을 실행한 체크아웃의 워크플로 파일에 있는 워크플로·job 이름만 적는다. 실행 기록에만 있는 이름(외부 PR이 정할 수 있다)은 글자가 무난해도 적지 않고 `(기타)`로 합친다. PR 제목·브랜치 이름 같은 외부 입력 문자열과 계정 이름은 옮기지 않는다(설계서 14.6절).
6. 잰 시점의 입력을 남기고 그것으로 다시 계산할 수 있다. `--save <파일>`은 읽은 기록을 보존 기록으로 남기고(있는 파일은 덮어쓰지 않는다), `--from <파일>`은 GitHub을 읽지 않고 그 파일로 계산한다. 같은 체크아웃에서 두 출력은 같은 글이다. 보존 기록에는 수, 날짜, 허용 목록에 있는 이름, 정해 둔 낱말만 있다(커밋 SHA, 브랜치 이름, 제목, 계정 이름, 허용 목록 밖의 이름·라벨이 없다).
7. `docs/harness/actions-cost.md`에 판단 절차(예산, 기준이 되는 입력, 다시 재는 때, 판단 시점 셋, 효과가 없을 때, 파일럿 실측, 예산을 넘는 결정), 기준선(2026-11-17~20, 비공개 기간. 잰 날짜와 명령), 기록 표가 있고 `docs/index.md`가 가리킨다. 기준선의 입력은 `lab/actions-cost/2026-11-17_2026-11-20.jsonl`에 남긴다. 검사 스크립트(`lab/actions-cost/check-doc.ts`)가 GitHub을 읽지 않고 아래를 본다: 문서의 기준선이 그 보존 기록으로 다시 계산한 출력과 같다, 예산 값이 제작자가 정한 값과 같다, 판단 절차의 항목마다 내용이 있다, 기록 표의 값이 보존 기록으로 계산한 값과 같고 판단이 예산과 맞다. 문서가 비었거나 값이 다르면 실패한다(step1의 AC가 문서를 망가뜨려 실패하는 것까지 확인한다).
8. 절감 수단마다 예상 절감, 잃는 보장, 바꿔야 하는 것, 되돌리는 방법, 사실관계의 확인 상태를 적은 ADR이 있고(step2에 ID로 적은 후보 18개를 모두 다룬다. 묶음 둘 이상과 묶음별 단가별 PR당 청구 분·PR당 금액·월 금액·예산 안인지), 상태(제안 또는 채택)와 제작자가 고른 수단·순서(고르기 전이면 추천 묶음·순서·이유)가 적혀 있다. 순서는 고른 수단을 모두 한 번씩 담는다. 검사 스크립트(`lab/actions-cost/check-adr.ts`)가 후보표의 칸, 묶음의 값과 계산, 결정의 줄을 보고, 비어 있거나 어긋나면 실패한다(step2의 AC가 ADR을 망가뜨려 실패하는 것까지 확인한다). 설계서, ADR 색인, 기술 부채 표가 ADR 파일을 가리킨다.
9. `node scripts/harness.ts check` 통과.
