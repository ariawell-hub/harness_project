# check-adr가 출처 주소 안의 날짜를 확인일로 받는다

- 목표: `lab/actions-cost/check-adr.ts`의 `checkAdr`가 후보표의 "확인 상태" 칸에서 확인한 날짜를 **출처 주소 밖에서만** 찾는다. 지금은 괄호 안 전체에서 `YYYY-MM-DD` 꼴을 찾아, 주소 안에 든 날짜(`https://example.com/blog/2026-11-01/pricing`)를 확인일로 받는다. 확인일을 적지 않은 칸이 검사를 지나간다.
- 변경: "확인 상태" 검사가 괄호 안의 글을 공백과 쉼표로 나눈 조각의 **처음에 온** 날짜만 확인일로 센다(판정 1회차 F1 뒤에 고쳤다). 날짜의 앞은 글의 처음·공백·쉼표여야 하고, 뒤에 ASCII 글자·숫자·기호가 이어지면 세지 않는다(뒤는 끝·공백·쉼표이거나 한글 같은 ASCII 밖의 글자다). 주소는 조각 하나이므로 그 안의 날짜는 조각의 처음이 아니다(`이름://` 없이 적은 주소의 경로·질의, 글 제목 안의 날짜도 같다). 주소 밖의 날짜가 하나 이상이고 모두 실재하는 날짜여야 하는 것은 그대로다. 주소 안의 날짜는 실재하지 않는 날짜여도 판정에 영향을 주지 않는다. 실패 메시지에 "출처 주소 밖에"를 더한다. https 주소가 있어야 하는 검사, "확인함(외부 사실 없음)", "확인 못 함"의 검사는 바꾸지 않는다. 검사를 약화하지 않는다(받던 틀린 꼴을 거부한다).
- 검증: node --test lab/actions-cost/test/check-adr.test.ts && node lab/actions-cost/check-adr.ts

## 의사결정 로그

- 결정(판정 1회차 F1 뒤): 주소를 찾아 빼지 않고, 공백·쉼표로 나눈 조각의 처음에 온 날짜만 센다. / 이유: 주소의 꼴을 정해 빼는 방식은 꼴마다 틈이 남는다(`이름://` 없는 주소, 날짜 앞의 `=`·`?`·`#`). 칸의 형식은 `확인함(주소, YYYY-MM-DD)`이고 날짜는 쉼표나 공백으로 띄어 적는다. 조각의 처음만 보면 주소가 어떤 꼴이든 그 안의 날짜를 세지 않는다. / 대가: `확인일:2026-11-22`처럼 날짜 앞에 글자를 붙여 쓴 꼴은 전에는 받았고 이제 거부한다(띄어 쓰면 된다. 지금의 ADR에는 그런 칸이 없다). / 버린 대안: 주소로 보이는 조각(`/`나 `.`이 든 조각)을 빼고 나머지에서 찾는다(무엇이 주소인지의 판단이 다시 틈이 된다).
- 결정(처음 구현, F1로 바꿨다): 주소를 빼는 것에 더해, 날짜가 홀로 선 낱말일 때만 확인일로 받는다. / 이유: 주소를 `이름://` 꼴로만 빼면 `이름://` 없이 적은 주소(`example.com/2026-11-01/b`)나 글 제목(`2026-11-01-coming-soon`) 안의 날짜가 같은 틈으로 남는다. / 버린 대안: 괄호 안을 쉼표로 나눠 날짜만 든 조각을 요구한다(`2026-11-22에 확인`처럼 지금 받는 꼴을 거부하게 된다. Issue의 범위보다 넓다).
