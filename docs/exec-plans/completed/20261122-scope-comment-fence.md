# scope 판정이 '관련 파일' 절의 HTML 주석 안에 있는 닫히지 않은 코드 펜스 뒤의 경로를 읽지 못한다

- 목표: `scope` 판정이 계획의 "관련 파일·문서" 절에서 범위 경로를 뽑을 때, HTML 주석 안에 있는 코드 펜스 줄(물결표나 백틱 셋)을 펜스로 읽지 않는다. 주석 뒤에 적은 경로가 범위에 든다(지금은 주석 안의 닫히지 않은 펜스 줄 뒤의 경로가 모두 빠져, 그 경로의 변경이 "범위 밖"으로 틀리게 경고된다).
- 변경: `scripts/gates/scope.ts`의 `scopePaths`가 주석과 펜스를 **먼저 열린 쪽**으로 가린다. 지금은 펜스 안의 줄을 먼저 빼고 그다음에 주석을 지워서, 주석 안의 펜스 여는 줄을 실제 펜스로 본다. 펜스 안의 `<!--`는 지금처럼 주석이 아니다(펜스 안의 글이다). 닫히지 않은 `<!--`는 지금처럼 주석이 아니다. 판정의 다른 부분(범위 안인지의 비교, 경고의 글)은 바꾸지 않는다. 검사를 약화하지 않는다(틀린 경고를 없앤다).
- 검증: node --test scripts/test/scope.test.ts

## 테스트 (먼저 쓴다)

- `scopePaths`(`scope.test.ts`에 테스트 하나를 더한다. 있던 테스트의 단언은 고치지 않는다):
  - 여러 줄 주석 안에 닫히지 않은 물결표 펜스 줄이 있어도 주석 뒤의 경로가 뽑힌다: `a.ts` 항목, `<!--`, `~~~`, `-->`, `b.ts` 항목 → `a.ts`, `b.ts`. 백틱 셋도 같다.
  - 주석 안의 경로는 지금처럼 빠진다(펜스 줄이 함께 있어도): `<!--`, `~~~`, `x.ts` 항목, `-->`, `b.ts` 항목 → `b.ts`.
  - 주석 안에 열고 닫은 펜스가 있는 꼴, 한 줄 주석 `<!-- ~~~ -->`은 지금과 같다(뒤의 경로가 뽑힌다).
  - 반대쪽(펜스가 먼저 열렸다)은 지금과 같다: 펜스 안의 `<!--`는 주석을 열지 않는다. 펜스가 닫힌 뒤의 경로가 뽑히고, 펜스 안의 경로는 빠진다.
  - 주석이 닫힌 줄의 나머지 글은 지금처럼 읽힌다(`--> ` 뒤에 적은 경로).
  - 닫히지 않은 `<!--`는 주석이 아니다(지금과 같다): 그 줄과 뒤의 줄에 적은 경로가 뽑힌다.
  - 주석 안의 `## ` 줄에서 절이 끝나지 않는다(주석 안의 글이다). 주석 밖, 펜스 밖의 `## ` 줄에서는 지금처럼 끝난다.
  - 긴 입력: 닫히지 않은 `<!--`가 든 줄이 20,000개인 글을 5초 안에 읽는다(뒤에 닫는 표식이 있는지를 줄마다 다시 찾지 않는다).

## 의사결정 로그

- 결정: 주석과 펜스를 한 번의 훑기에서 먼저 열린 쪽으로 가린다. / 이유: 둘 중 하나를 먼저 통째로 지우면 다른 쪽 안에 있는 표식을 잘못 읽는다(지금은 주석 안의 펜스, 순서를 바꾸면 펜스 안의 주석). 마크다운이 읽는 방식과 같다. / 버린 대안: 주석을 먼저 지우고 펜스를 가린다(펜스 안의 `<!--`가 뒤의 경로를 지운다).
- 결정: 닫히지 않은 `<!--`는 지금처럼 주석으로 보지 않는다. / 이유: 지금의 `stripHtmlComments`가 그렇게 읽는다(닫는 표식이 있어야 지운다). 주석으로 보면 절의 끝까지 경로가 빠져 틀린 경고가 는다.

## 발견 사항

- `scripts/lib/plan.ts`의 `sections`는 펜스 줄(백틱이나 물결표 셋으로 시작하는 줄)마다 코드 블록 안팎을 뒤집고, 주석 안인지는 보지 않는다. 계획의 절 안에 여러 줄 주석이 있고 그 안에 닫히지 않은 펜스 줄이 있으면 뒤의 `## ` 제목들을 읽지 못해 뒤의 절이 그 절에 합쳐진다(확인: "관련 파일·문서" 절의 주석 안에 `~~~` 한 줄을 두면 절 목록이 그 절 하나뿐이다). 계획 해시에 묶이는 글이 늘고 필요한 절이 없다고 읽히는 쪽이라 틀린 통과를 만들지는 않는다. `scopePaths`는 이 변경 뒤로 주석 밖의 `## ` 줄에서 그치므로 범위 경로는 바르게 읽는다. `sections`는 계획 해시의 기준이라 이 Issue(소규모, 위험도 낮음)에서 고치지 않았다. 제작자에게 보고한다. → 처리: 해당 없음
